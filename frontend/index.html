🎓 Introduction to Cache Memory

Cache memory is a small, extremely fast memory located between the CPU and main memory (RAM). Its purpose is to hold copies of frequently accessed memory blocks so the CPU can retrieve data quickly without waiting for slower RAM.

Analogy: Think of your desk as the cache. You keep the most-used books (data) on your desk (cache) so you don't have to walk to the library (RAM) every time you need them.

When the CPU needs data, it first checks the cache. If it finds it there (a cache hit), it retrieves the data instantly. If not (a cache miss), it fetches the data from RAM and also stores a copy in the cache for future use.

🏗️ Memory Hierarchy

Modern computers organize memory into a hierarchy based on speed and cost:

  • Registers — fastest, inside the CPU, tiny (bytes)
  • L1 Cache — very fast, on-chip, small (32–64 KB)
  • L2 Cache — fast, on-chip or near-chip (256 KB – 4 MB)
  • L3 Cache — shared, slower (4 MB – 32 MB)
  • RAM (Main Memory) — large, slower (4–64 GB)
  • SSD / HDD (Secondary Storage) — huge, very slow
Principle of Locality: Programs tend to access the same data repeatedly (temporal locality) and access nearby memory addresses (spatial locality). Cache exploits both principles.

💾 Cache Memory Basics

Cache Lines (Cache Blocks)

Cache memory is divided into fixed-size units called cache lines (or cache blocks). Each cache line holds one memory block plus a tag (to identify which memory block is stored) and a valid bit (to indicate whether the data is valid).

Structure of a Cache Line: ┌─────────┬─────────────┬──────────────────────────┐ │ Valid │ Tag │ Data (block) │ │ bit │ │ │ └─────────┴─────────────┴──────────────────────────┘

Number of Cache Lines

Number of Cache Lines = Cache Size / Block Size Example: 64 B cache / 4 B block = 16 cache lines

Number of Memory Blocks

Number of Memory Blocks = Main Memory Size / Block Size Example: 256 B memory / 4 B block = 64 memory blocks

✅ Cache Hit & Cache Miss

Cache Hit

A cache hit occurs when the CPU requests data and that data is already present in the cache. The CPU retrieves it directly — fast!

Cache Hit: CPU → Cache → Found! → Return data to CPU

Cache Miss

A cache miss occurs when the requested data is NOT in the cache. The CPU must fetch it from main memory (slow). The block is then loaded into the cache.

Cache Miss: CPU → Cache → Not found → Go to RAM → Load block into cache → Return to CPU

Types of Cache Misses

  • Cold Miss (Compulsory): First-ever access to a block.
  • Conflict Miss: Two blocks map to the same line; one replaces the other.
  • Capacity Miss: Cache is too small to hold all needed blocks.

🗺️ Direct Mapping

In direct mapping, each main memory block maps to exactly one specific cache line. It is the simplest and fastest lookup method.

Memory Block Number = Memory Address / Block Size Cache Line Number = Memory Block Number % Number of Cache Lines Tag = Memory Block Number / Number of Cache Lines Block Offset = Memory Address % Block Size

Example (256B memory, 64B cache, 4B block):

Number of cache lines = 64 / 4 = 16 Address 0: Block = 0 / 4 = 0, Line = 0 % 16 = 0, Tag = 0 / 16 = 0 Address 4: Block = 4 / 4 = 1, Line = 1 % 16 = 1, Tag = 1 / 16 = 0 Address 64: Block = 64 / 4 = 16, Line = 16 % 16 = 0, Tag = 16 / 16 = 1 Address 128: Block = 128/4 = 32, Line = 32 % 16 = 0, Tag = 32/16 = 2
Disadvantage: Addresses 0, 64, 128, 192 all map to cache line 0. Accessing them alternately causes repeated evictions (conflict misses).

🔀 Fully Associative Mapping

In fully associative mapping, any memory block can be placed in any cache line. There is no fixed mapping between memory blocks and cache lines.

Memory Block Number = Memory Address / Block Size Block Offset = Memory Address % Block Size Tag = Memory Block Number (the entire block number is the tag) Index = none (search all lines)

How it works:

  • To find a block, the cache must search ALL cache lines (associative search).
  • When the cache is full and a miss occurs, a replacement algorithm decides which block to evict.
  • No conflict misses — most flexible, but hardware is expensive for large caches.
Address format: [ TAG | OFFSET ] — no index field.

🗂️ Set Associative Mapping

Set associative mapping is a compromise between direct and fully associative. The cache is divided into S sets, each containing N lines (N-way). A memory block maps to exactly one set but can occupy any line within that set.

Number of Lines = Cache Size / Block Size Number of Sets = Number of Lines / Associativity (N) Set Index = Memory Block Number % Number of Sets Tag = Memory Block Number / Number of Sets Block Offset = Memory Address % Block Size

Example (2-way, 4 sets):

Block 0 → Set 0 (can go to line 0 or 1 of set 0) Block 1 → Set 1 Block 4 → Set 0 (same set as block 0, different tag) Block 8 → Set 0 (same set — if set full, replacement needed)
Advantage: Reduces conflict misses compared to direct mapping. More practical than fully associative for large caches.

🔄 FIFO – First In First Out

The FIFO replacement policy evicts the block that was loaded into the cache earliest (first inserted = first removed).

Key Rule:

  • Track the insertion order of blocks, not access order.
  • A cache hit does NOT update the block's position in the queue.
  • When eviction is needed, remove the block at the front of the queue (oldest).
Queue: [B0 ← oldest, B1, B2, B3 ← newest] Access B5 (miss, cache full): Evict B0 (front of queue) Insert B5 at back: Queue: [B1, B2, B3, B5] Access B1 (hit): Queue UNCHANGED: [B1, B2, B3, B5] ← B1 stays old!

⏱️ LRU – Least Recently Used

The LRU replacement policy evicts the block that has not been accessed for the longest time — the least recently used block.

Key Rule:

  • Track the last access time of every block.
  • A cache hit DOES update the block's recency timestamp.
  • Evict the block with the smallest (oldest) access timestamp.
State: B0(t=1), B1(t=2), B2(t=3), B3(t=4) (t=time of last access) Access B5 (miss, cache full): LRU victim = B0 (smallest t=1) Insert B5 (t=5) State: B1(t=2), B2(t=3), B3(t=4), B5(t=5) Access B1 (hit): B1 recency updated to t=6 State: B2(t=3), B3(t=4), B5(t=5), B1(t=6) ← B1 is now newest!
FIFO vs LRU: FIFO uses insertion order; LRU uses access order. LRU generally performs better because recently used data is more likely to be reused.

🏷️ Address Fields: TAG | INDEX | OFFSET

A memory address is split into three fields that the cache hardware uses to locate data:

32-bit Address: ┌───────────────────┬────────────┬────────────────┐ │ TAG │ INDEX │ OFFSET │ │ (tag_bits) │(index_bits)│ (offset_bits) │ └───────────────────┴────────────┴────────────────┘ offset_bits = log₂(Block Size) index_bits = log₂(Number of Sets) [0 for Fully Associative] tag_bits = 32 - index_bits - offset_bits

Field meanings:

  • OFFSET: Selects a specific byte within a block.
  • INDEX / SET INDEX: Selects the cache line (DM) or set (SA).
  • TAG: Stored in the cache line to verify which memory block is cached.

Example (64B cache, 4B block, 16 lines, Direct Mapping):

offset_bits = log₂(4) = 2 index_bits = log₂(16) = 4 tag_bits = 32 - 4 - 2 = 26 Address 68 (binary: 00000000 00000000 00000100 01000100): Offset = 68 % 4 = 0 → byte 0 of the block Block = 68 / 4 = 17 Index = 17 % 16 = 1 → cache line 1 Tag = 17 / 16 = 1 → tag stored is 1

📊 Performance Statistics

Total Accesses = Total number of memory reference requests Cache Hits = Number of accesses found in cache Cache Misses = Number of accesses NOT in cache = Total - Hits Hit Ratio = Cache Hits / Total Accesses Miss Ratio = Cache Misses / Total Accesses Hit Percentage = Hit Ratio × 100% Miss Percentage = Miss Ratio × 100% Verification: Hit% + Miss% = 100% (always)
Good cache performance typically means a hit ratio above 90%. Modern CPUs achieve 95%+ hit ratios with well-designed cache hierarchies.

Special Case – Zero Accesses:

If total accesses = 0, all ratios are defined as 0 to avoid division by zero.

🎯 Project Objective

To develop an interactive application that demonstrates how cache memory works between the CPU and main memory. The simulator models Direct Mapping, Fully Associative Mapping, and Set Associative Mapping techniques with FIFO and LRU replacement policies. It provides step-by-step visualization of memory accesses, hit/miss detection, block replacement, and address field calculation — making computer architecture concepts accessible to students.
